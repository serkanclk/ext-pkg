# ING SQL Developer for VS Code - v2.6.0 Release Notes

Welcome to version **2.6.0** of the ING SQL Developer extension for VS Code! This update packs massive enhancements to the core coding experience, bringing real-time feedback, smarter completion, and more customization to make you as productive as you are in traditional desktop IDEs.

Below is an extensive guide on what is new and how to use the latest features.

---

## 1. Smart Context-Aware IntelliSense 🧠

A top request! The autocomplete engine has been rewritten to be deeply context-aware, fetching live metadata from the database dynamically while keeping your editor fast. 

### How to use it:
- **Dot-column completion**: Type a table name or an alias followed by a dot (e.g., `TBL_A.` or `a.`). The IntelliSense will immediately suggest all columns for that specific table, complete with data type information and comments.
- **`SELECT` and `WHERE` awareness**: Simply start typing inside a `SELECT`, `WHERE`, `ORDER BY`, or `HAVING` clause, and the extension will prioritize column names from the tables currently referenced in your `FROM` clause over random keywords.
- **`FROM` and `JOIN` completion**: After typing `FROM` or `JOIN`, the extension knows you need a table, and will suggest tables and views directly.
- **Schema exploration**: Type a schema name followed by a dot (e.g., `HR.`), and the extension will query Oracle and suggest all tables and views belonging to that schema.

*Note: Column data is fetched lazily and cached for 5 minutes, ensuring fast typing without overloading your database connection.*

---

## 2. Real-Time SQL Diagnostics & Error Pinpointing 🐛

You no longer have to run the entire query and squint at the output to find a syntax mistake or a missing parenthesis.

### How to use it:
- **As you type**: The extension constantly analyzes your SQL script. If you leave a string literal unclosed (`'`), leave a block comment unterminated (`/*`), or have unmatched parentheses (e.g., an extra `)`), you will see red "squiggly" underlines right in the editor.
- **After execution**: If an Oracle execution fails, you previously got a generic toast popup. Now, the extension leverages Oracle's internal error offsets to draw a red squiggly *on the exact offending word/token* in your script, along with the specific `ORA-XXX` error code in the hover tooltip and the VS Code **Problems** panel.

## 3. Results Grid & Export Customization ⚙️

We've brought over the custom preferences you loved in native Oracle SQL Developer.

### `ingSql.resultGrid.nullDisplay`
You can now define exactly how `NULL` values are displayed in the results grid and in text-heavy exports (CSV, HTML).
- **How to use**: Go to VS Code Settings → search for `ingSql.resultGrid.nullDisplay`.
- **Default behavior**: It defaults to `(null)` (matching Oracle SQL Developer), but you can select `(NULL)`, leave it as a blank space, or type any custom string (e.g., `<EMPTY>`) you want.

### `ingSql.resultGrid.useEditorFont`
Variable-width fonts make scrolling through large grids difficult because columns don't align cleanly.
- **How to use**: Go to VS Code Settings → search for `ingSql.resultGrid.useEditorFont`.
- **Default behavior**: It defaults to `true`. When turned on, the result grid automatically inherits your `editor.fontFamily` (which is typically a monospace font like Consolas or Fira Code) allowing for perfect column alignment.

*Bonus: Tinkering with these two settings, as well as changing your VS Code font size, will apply to the Results Panel live, instantly! No reload required.*

---

## 4. Package Body Visibility in Object Browser 📦

**What changed**: Previously, expanding a Package in the Object Browser only mapped to the `PACKAGE` specification, making `PACKAGE BODY` invisible. 
**How to use it**: Navigate to the Object Browser. When you expand any Package, you will now see two unified sub-nodes:
- **Spec**: View or compile the Package Specification
- **Body**: View or compile the Package Body

---

## 5. Persistent SQL Snippets (Cross-Browser Safe) 💾

**What changed**: A silent architectural fix. Snippets were previously stored in a lightweight internal cache (`globalState`) which VS Code partitions per-browser window (e.g., Chrome vs Edge vs IDE).
**How it works now**: All snippets are automatically migrated and persisted to a localized robust JSON file (`snippets.json`). Now, no matter where you reload your environment or which client you log into, your snippets will synchronize and persist safely without deletion.
